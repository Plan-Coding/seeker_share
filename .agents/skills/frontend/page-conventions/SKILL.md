# 通用页面规范(Page Conventions)

适用于本项目**所有页面**(共享广场、工具箱、文档库、权限管理等)。工具箱工具遵循本规范,同时保持「零第三方依赖、数据不出本机」。

## 列表与表格(硬性要求)

- **搜索**:列表必须提供关键词搜索(数据量小用前端过滤,数据量大用后端搜索接口),按标题/内容/标签等关键字段匹配。
- **分页**:列表超过一页容量(默认每页 20 条)时必须分页,提供上一页/下一页、页码与总条数;翻页时保持当前搜索与筛选条件。
- **数据量小**的列表(如角色、设备)可全量展示但必须有搜索;**数据量可能增长**的列表(用户、文档、分享记录等)必须「分页 + 搜索」。
- 搜索无结果时展示「未找到匹配项」等空状态,不出现空白区域。

## 常见页面规范

- **空状态**:无数据时展示友好中文提示(如「还没有内容」),而非空白。
- **危险操作**(删除/清空/停用/重置等):执行前二次确认(confirm 或 dialog),说明影响范围与不可恢复性;删除按钮用 `danger` 样式区分。
- **受保护数据**:内置账户(如 admin)、当前登录账户不可删除/停用,后端强制校验,前端同样禁用对应控件。
- **操作反馈**:成功/失败统一 toast 提示;错误信息为简体中文、可理解,不暴露技术细节。
- **表单**:前端先做必填/格式校验 + 后端兜底;提交中禁用按钮防止重复提交;成功后重置表单并刷新相关列表。
- **状态标识**:用状态徽章(status-chip)展示状态(正常/已锁定/已停用/待改密码等)。
- **加载与失败**:异步数据展示加载态,失败时提示并允许重试(刷新按钮)。

## 验证

- 浏览器实测:翻页、搜索、空结果、删除确认、失败提示均正常
- 涉及 JS:`node --check` 通过
